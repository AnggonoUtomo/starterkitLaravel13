## Purpose

Generator adalah jalur resmi untuk membuat module dan submodule agar output
memiliki struktur, contract, permission identity, test, dan dokumentasi yang
konsisten. Generator tidak menghasilkan business logic yang belum ditentukan.
Module baru wajib dibuat melalui `module:make`. Pembuatan manual hanya boleh
untuk framework maintenance atau kasus khusus yang memiliki exception ADR,
review architect, dan test output yang setara generator.

## Baseline Objectives

- Membuat module pada `app/Modules/{Domain}/{Submodule}`.
- Menghasilkan `module.json`, `module.php`, dan `permissions.php`.
- Menghasilkan layer DDD-lite dan communication boundary.
- Menghasilkan migration, factory, seeder, route, test, dan README bila profile memerlukannya.
- Menghasilkan frontend page/component dalam owner module.
- Menjalankan naming, dependency, conflict, dan forbidden package validation.
- Menyediakan output human-readable dan `--json`.

## Supported Baseline Commands

```bash
php artisan module:make Platform AccessControl
php artisan module:make Platform UserManagement
php artisan module:make Platform AuditLog
php artisan module:make Platform SystemSetting
php artisan module:list
php artisan module:inspect Platform/AccessControl
php artisan module:discover
php artisan module:validate
```

`module:enable` dan `module:disable` juga termasuk baseline lifecycle command.

CRUD, feature, resource, dan API generator belum menjadi baseline pertama.

## Generator Profiles

Profile adalah preset output generator yang versioned dan memiliki test sendiri.
Baseline pertama menyediakan profile `platform` untuk AccessControl,
UserManagement, AuditLog, dan SystemSetting. Profile `business`, `integration`,
dan `minimal` menjadi roadmap dan belum wajib diimplementasikan.

```bash
php artisan module:make Platform AccessControl --profile=platform
```

Profile `platform` menghasilkan DDD-lite layer, manifest, runtime config,
permission identity, provider, policy/contract placeholder, database boundary,
frontend ownership structure, test dasar, dan README.

## Generator Options

Semua generator filesystem mendukung:

- `--dry-run`: menampilkan planned changes tanpa menulis.
- `--force`: mengizinkan overwrite eksplisit.
- `--json`: machine-readable output.
- `--no-tests`/`--no-docs`: hanya dengan explicit confirmation dan bukan default.
- `--profile`: memilih profile output yang telah disetujui.

Default generator fail-safe dan tidak menimpa file.

`--force` pada terminal interaktif wajib meminta confirmation. Pada CI atau
non-interactive environment, overwrite hanya boleh dilakukan dengan kombinasi
eksplisit `--force --yes`; `--force` tanpa `--yes` harus gagal.

## Input Contract

Generator menerima:

- domain/module name;
- submodule name;
- optional profile;
- optional namespace/path yang tervalidasi;
- dependency list yang terdaftar pada manifest.

Input wajib divalidasi sebelum filesystem berubah. Module name memakai PascalCase;
command argument boleh menerima kebab-case yang dinormalisasi secara eksplisit.

## Generated Metadata

### `module.json`

Minimal metadata:

```json
{
  "name": "AccessControl",
  "namespace": "App\\Modules\\\\Console\\AccessControl",
  "version": "1.0.0",
  "status": "active",
  "domain": "Platform",
  "path": "app/Modules/Console/AccessControl",
  "provider": "App\\Modules\\\\Console\\AccessControl\\ServiceProvider",
  "dependencies": [],
  "permission_source": "permissions.php"
}
```

### `permissions.php`

Permission identity dimiliki module:

```php
return [
    [
        'key' => 'access_control.role.manage',
        'description' => 'Manage roles',
        'module' => 'AccessControl',
        'sensitive' => false,
    ],
    [
        'key' => 'access_control.permission.manage',
        'description' => 'Manage permissions',
        'module' => 'AccessControl',
        'sensitive' => true,
    ],
]; 
```

AccessControl melakukan discovery dan sync permission dari module valid; owner
permission tidak berpindah ke AccessControl. Setiap item wajib memiliki `key`,
`description`, `module`, dan `sensitive`; key bersifat unik secara global.

### Module README

Profile `platform` selalu menghasilkan `README.md` module. Opsi `--no-docs`
hanya boleh dipakai dengan confirmation eksplisit dan menghasilkan diagnostic
bahwa README wajib dilengkapi sebelum module dapat dinyatakan ready.

## Generated Code Rules

- Strict typing dan namespace benar.
- ULID migration/model/factory/fixture konsisten.
- Tidak menghasilkan business logic palsu.
- Cross-module dependency hanya contract/communication layer.
- Event memakai typed payload dan correlation ID.
- Security-sensitive output memiliki policy, permission, dan audit hook placeholder.
- Permission identity berada pada `permissions.php` module.
- Generated code tidak menggunakan Wayfinder atau Laravel Boost.

## Conflict and Safety Rules

1. Validate environment dan forbidden dependency.
2. Validate input, target path, namespace, manifest, dan dependency.
3. Build planned file list.
4. Jika conflict dan tidak ada `--force`, berhenti tanpa perubahan.
5. `--dry-run` hanya menampilkan plan.
6. `--force` mencatat file yang ditimpa dan meminta confirmation interaktif;
   CI wajib memakai `--force --yes`.
7. Generator menulis ke staging directory dan melakukan atomic promotion setelah
   seluruh output tervalidasi.
8. Jika staging gagal, temporary output dihapus tanpa menyentuh target.
9. Jika promotion gagal, operation log menjalankan cleanup untuk file yang dibuat;
   overwrite memiliki backup/restore strategy.
10. Output tidak pernah menampilkan secret.

Generator tidak boleh otomatis uninstall dependency forbidden. Generator
menampilkan diagnostic, remediation command yang aman, dan menghentikan proses.

## Output Contract

Default output human-readable. `--json` wajib memiliki:

```json
{
  "success": true,
  "code": "MODULE_CREATED",
  "message": "Module created successfully.",
  "data": {
    "module": "AccessControl",
    "path": "app/Modules/Console/AccessControl",
    "created": []
  },
  "diagnostics": []
}
```

Error memiliki exit code non-zero, code stabil, message actionable, dan
diagnostics tanpa sensitive payload.

## Starter Kit Validation

Sebelum generate, verifikasi PHP 8.4+, Laravel 13, React starter kit, Inertia,
React, TypeScript, Vite, Tailwind, shadcn/ui, PostgreSQL, Redis, Ziggy, approved
Spatie package, serta absensi Wayfinder/Laravel Boost.

## Generator Test Requirements

- Naming/namespace validation.
- Manifest and permission schema.
- Dry-run no-write.
- Conflict no-write.
- Force overwrite.
- Partial write cleanup.
- JSON output contract.
- Generated structure snapshot.
- ULID migration output.
- Module discovery/validation integration.
- Forbidden dependency failure.

## Future Enhancements

Feature, resource, CRUD, API, dashboard, report, workflow, dan multi-tenant
generator hanya ditambahkan melalui specification, profile version, test, dan
ADR yang sesuai.
